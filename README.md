# Bus bunching prediction - SL GTFS-RT, 2024

Scripts for predicting bus bunching on Stockholm (SL) bus lines from 2024
GTFS-Realtime data. This repository contains code only: no data, trained
models, figures or reports. Everything is regenerated by the scripts below
from the raw input files.

See `bunching-implementation-plan.md` for the project plan (research
questions, hypotheses, phases, known traps) and `docs/` for the methodology
(data description, headway/label construction, feature engineering, split and
model choice). The docs quote numbers from the original run; your outputs will
land in `reports/` and `figures/` when you run the pipeline.

## Input data

Place these files in the repository root (next to `src/`):

| File | Used by |
|------|---------|
| `gtfs_rt_202401.csv.gz` ... `gtfs_rt_202412.csv.gz` (12 monthly files) | `src/ingest.py` (read as `gtfs_rt_2024*.csv.gz`) |
| `stops.csv` | `src/features.py`, `src/eda_figures.py`, `src/weather.py` |
| `transfers.csv` | `src/features.py` |
| `service_alerts_2024.parquet` | `src/features.py` |
| `routes.csv`, `trips.csv` | GTFS static reference, not read by the scripts |

Only `src/weather.py` needs internet access (Open-Meteo, fetched once and
cached to `data/processed/weather.parquet`). The raw input is several GB and
the processed tables reach tens of GB, so allow for that on disk.

## Setup

```
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

Run every command below from the repository root; paths are relative to it.

## Running the pipeline

Run in this order; each step reads what the previous ones wrote. Steps 1-7, 9-13 and 15
use the main environment, steps 8 and 14 use the separate Keras environment
(see below), and `compare_models.py` / `compare_tuned.py` need the Keras
results, so they come after it.

```
# main environment (.venv)
python3 src/ingest.py            # 1. Phase 1: raw csv.gz -> data/processed/bus_subset.parquet
python3 src/headways.py          # 2. Phase 2: -> data/processed/headways.parquet
python3 src/weather.py           # 3. Open-Meteo fetch -> data/processed/weather.parquet (network, run once)
python3 src/features.py          # 4. Phase 4: -> data/processed/model_dataset.parquet
python3 src/eda_figures.py       # 5. Phase 3: -> figures/fig1..7_*.png
python3 src/models.py            # 6. Phase 5: logreg + HGB, all 5 horizons -> models/*.joblib
python3 src/sequence_data.py     # 7. Phase 5: -> data/processed/sequence_dataset.parquet

# Keras environment (.venv312)
python3 src/sequence_model.py    # 8. -> models/sequence_k*.keras, models/phase5_keras_results.json

# main environment (.venv)
python3 src/compare_models.py    # 9. -> figures/fig8_pr_auc_vs_horizon.png, reports/results_tables.md
python3 src/diagnostics.py       # 10. Phase 6: -> reports/phase6_diagnostics.json (~10 min)
python3 src/split_variants.py    # 11. split comparison: -> reports/split_comparison.json (~6 min)
python3 src/tuning.py stage1     # 12. tuning + PCA study at k=3 -> reports/tuning_stage1.json (~30 min)
python3 src/tuning.py stage2     # 13. refit winners at k=1,2,5,8 -> reports/tuning_stage2.json (~25 min)

# Keras environment (.venv312)
python3 src/tuning_keras.py      # 14. -> reports/tuning_keras.json, models/tuned_sequence_k*.keras (~1 h)

# main environment (.venv)
python3 src/compare_tuned.py     # 15. -> figures/fig9_tuned_pr_auc_vs_horizon.png, reports/tuned_results_table.md

# both environments, run from the repo root (~7-8 h, resumable, keeps the Mac awake)
./run_tuning_per_k.sh            # 16. separate search per horizon k=1,2,3,5,8 for HGB, logreg and Keras
                                 #     -> reports/tuning_per_k.json, reports/tuning_keras_per_k.json, models/perk_*
                                 #     (./run_tuning_per_k.sh --smoke checks the pipeline in ~2 min)
```

`src/export_encoded_sample.py` is an optional helper that exports a small
encoded feature sample to `data/processed/`.

### Keras environment

TensorFlow has no wheel for Python 3.14, so the two Keras scripts
(`sequence_model.py`, `tuning_keras.py`) use a separate Python 3.12
environment:

```
python3.12 -m venv .venv312 && source .venv312/bin/activate
pip install -r requirements-keras.txt
```

## Outputs

All outputs are written to `data/processed/`, `models/`, `figures/` and
`reports/`. Those folders exist in the repo (via `.gitkeep`) but their
contents are git-ignored.
